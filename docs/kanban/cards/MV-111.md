## What this is

The second layer of MV-105. Layer A (PR #70) captured optional `secondaryGoals`
(max 2, disjoint from the primary `goal`) but shipped them **deliberately inert** —
they move neither the verdict nor the match ordering. Layer B turns that inert
capture into ONE honest sentence: when a student's **primary** goal and one of
their **secondary** goals genuinely pull in different directions, we surface a
calm trade-off note. It is the goal-equivalent of `lib/scoring/field-note.ts`'s
`competitivenessNote` — an honest note that **never moves a score or a sort**.

Founder decision: **ship Option 1** (inline trade-off note, context-only).
Rejected during brainstorm: silent secondary re-rank (invisible + uneven data),
goal-weighted fit score (breaks inertness, fabricates a verdict), and the modal
pattern (a goal tension is *knowable, not fixable*, so the note is inline and
non-blocking, never a modal).

## v1 tension pairs (framing-only — no citation needed)

Ordered priority list; **exactly one** note ever shows, first match wins:

1. `permanent-residency ↔ highest-ranked` (higher priority)
2. `lowest-cost ↔ highest-ranked`

Both assert **no external fact** — they name a directional trade-off in what the
student is optimising for. That is framing, not a data point, so it clears the
same honesty bar as `competitivenessNote` and carries **no `source`/`lastVerified`**.
Fires symmetrically (either goal may be the primary; the copy names both).

## Deliberately deferred to a sourced follow-up

Each of these asserts a **citable fact** and must carry a `source` before shipping:

- `fastest-admission ↔ research` — an admissions-timeline claim.
- Synergy pairs: `highest-ranked ↔ research` (needs a Go8 research-intensity
  source), `permanent-residency ↔ lowest-cost` (needs a regional-study migration
  source).
- `best-employment` pairs stay **silent** — no program-level employment data.

## The inertness guarantee (load-bearing)

- The note is an **independent pure function** (`lib/goals/conflicts.ts`), derived
  purely from the two goal selections; its result is display-only.
- `secondaryGoals` is **never** routed into `runAssessment` (`lib/scoring/engine.ts`),
  `lib/plan/generator.ts`, or the matches sorter (`applyPreference` /
  `lib/matches/preference.ts`) — the sorter doesn't even receive secondaries, so
  ordering is **structurally** inert.
- The existing `tests/scoring/secondary-goals-inert.test.ts` (the Layer A honesty
  guarantee) is untouched and still green — re-run as part of this slice.
