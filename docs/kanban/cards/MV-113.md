# MV-113 — Hotfix: MV-112 landing layout bugs (reveal stuck hidden + verdict bar inline)

**Column:** Done · **Priority:** P1 · **Owner:** agent
**Branch:** `mv-113-landing-visual-hotfix` (off `master`) · **Merge:** PR #74 squash-merged to `master` `871f9d0`, deployed 2026-07-08
**Follows:** [MV-112](MV-112.md) (v7 landing redesign)

## What this is

A post-merge **live visual check** of the freshly-shipped MV-112 landing found it
badly broken in production: every scroll-reveal-wrapped section artifact was
invisible, and the verdict-panel meter bars overlapped and clipped. Two bugs that
a green **1891-test jsdom suite passed clean** — jsdom has no layout engine, so it
cannot see `display:none` removing an element from flow or an inline box ignoring
`height`.

## The two bugs

### 1. Reveal stuck hidden (all artifacts invisible)

`components/marketing/reveal.tsx` named its post-mount pre-reveal phase class
`"hidden"`. That collides with **Tailwind's global `.hidden{display:none}`**
utility, which is also in scope on the page. The scoped `.mv-reveal.hidden` rule
only set `opacity:0`, so Tailwind's `display:none` won by specificity/cascade →
the element left layout → **`IntersectionObserver` can never report a
`display:none` element as intersecting** → the reveal was stuck hidden forever.
Everything wrapped in `<Reveal>` (plan accordion, documents checklist, guide
thread, freshness table, close CTA) never appeared.

**Fix:** renamed the phase token `"hidden"` → `"off"`. The scoped
`.mv-landing .mv-reveal.off` sets `opacity:0; transform:translateY(18px)` (an
opacity-only hide that keeps the layout box observable). Changed in
`reveal.tsx` (the `Phase` union + `setPhase("off")`) and `app/(marketing)/landing.css`.

### 2. Verdict meter bar inline (overlap + clip)

`components/marketing/verdict-panel.tsx` renders the dimension meter as
`<span className="bar">…</span>`. A `<span>` is `display:inline` by default, so
its `height:6px` was **ignored** and the bar ballooned to line-box height (~47px),
overlapping the next dimension row and clipping the final fill.

**Fix:** `.mv-landing .bar{display:block}` (prepended to the existing rule).

## Regression guards (jsdom can't see layout, so assert the class contract)

- `tests/components/marketing/reveal.test.tsx` — with motion allowed, the
  post-mount pre-reveal class must be `off`, never `hidden`, and the observer must
  be attached.
- `tests/styles/landing-css.test.ts` — `.mv-reveal.off` exists with `opacity:0`
  and `.mv-reveal.hidden` does **not**; `.mv-landing .bar` is `display:block` with
  `height:6px`.

## Evidence

- Both fixes verified **live** in the preview end-to-end: hero, verdict panel
  (clean thin 6px bars), plan accordion, checklist, guide thread (with "verified"
  citation), freshness table (5 rows), close CTA all render.
- Gate green: typecheck 0, lint 0 errors (only the pre-existing `build.mjs`
  warning), 1894 tests (+3 guards).
- PR [#74](https://github.com/Spooderinbed/merovisa/pull/74) → `master` `871f9d0`.

## Lesson

A green suite + jsdom cannot catch layout/CSS bugs (no layout engine). **Always do
a live browser visual pass after shipping a CSS-heavy page.** See also [MV-114](MV-114.md).
