## What this is

The fifth and final jsdom-blind slice: four **cosmetic** defects a green ~1900-test
jsdom suite cannot catch because jsdom has no layout engine (pixel alignment, width
reflow) and never advances real animation/scroll timers. None is a trust bug; all are
polish that reads as "AI-generated sloppiness" if shipped.

## Findings in this slice

### #8 — `components/dashboard/journey-rail.tsx` (connector off the dot centres)
The baseline connector was `top-[13px]`, but each dot's centre sits at `py-1` (4px) +
half `h-2.5` (5px) = **9px** from the top of the `<ol>`, so the line floated 4px below
the dots. Fix: `top-[13px]` → `top-[9px]`. (The sibling `outcome-funnel.tsx:63` rail,
which has no `py-1`, correctly uses `top-[5px]` — the same "line through the dot
centres" pattern, confirming the geometry.)

### #9 — `components/matches/matches-tabs.tsx` (active-tab width jitter)
The active tab gains `font-medium` (500), making it ~1–2px wider than its inactive
siblings; on every switch the whole tablist reflows sideways. Fix: keep the active tab
bold (the WCAG 1.4.1 non-colour weight cue) but reserve the bold width on **every** tab
via a hidden, `aria-hidden`, always-`font-medium` ghost of the label, grid-stacked
(`grid place-items-center`, both spans at `col-start-1 row-start-1`) under the visible
label. The cell is pinned to the bold width, so selection never nudges siblings. The
accessible name still comes only from the visible label (ghost is `aria-hidden`).

### #6 — `components/marketing/freshness-table.tsx` (pulse burned off-screen at mount)
`verified` was hardcoded on every `.frow` at mount. Its CSS drives the `.vdot` opacity
**and** a one-shot `vpulse` animation, so all five verification pulses fired at mount —
while the table is far below the fold — and the user never saw them. The on-scroll IO
sweep only toggled `.lit`. Fix: drive `verified` from state, applied per row **as the
sweep reaches it** (alongside `.lit`) so the pulse fires in view; reduced-motion / no-IO
users get the static end-state applied at once (the `vpulse` @keyframes is already gated
behind `prefers-reduced-motion:no-preference`). The provenance **text**
(`verifiedCitation` + next-check) is unconditionally rendered — unchanged, no-JS-safe.

### #10 — `components/marketing/guide-thread.tsx` (post-unmount setState)
The IO-effect cleanup was `return () => obs.disconnect()` — it did not bump
`runId.current`, so an in-flight autoplay typewriter kept scheduling `setState` after
unmount (bounded ~18s, no crash, but a real leak). Fix: bump `runId.current` in cleanup
so every in-flight `play()`/`type()` loop sees its id go stale and bails.

## Approach

Each is surgical and presentational. #8 is a one-token offset. #9 preserves the exact
visual (active bold, inactive regular) while making width state-invariant. #6 moves an
existing class from hardcoded to sweep-driven. #10 is a one-line cleanup. No trust
dimension, no data change.

## Test plan (jsdom-visible contracts, RED-first)

- **#8:** the connector `<div>` inside the `<ol>` carries `top-[9px]` and not `top-[13px]`.
- **#9:** an *inactive* tab is not itself `font-medium`, yet contains an `aria-hidden`,
  `invisible`, `font-medium` ghost of its own label (bold width reserved without the tab
  being bold). Existing WCAG test (active button keeps `font-medium`) stays green.
- **#6:** SSR (no effects) renders `class="frow"` ×5 with **zero** `frow verified`
  (pulse staged, not pre-fired) while the provenance text is present ×5; driving a mocked
  IO intersection + advancing the stagger timers marks all rows `verified`; reduced-motion
  applies all `verified` at once with no sweep.
- **#10:** with fake timers + a mocked IO firing intersection, starting autoplay leaves a
  timer pending; after `unmount()` and flushing, `vi.getTimerCount()` is **0** (the loop
  bailed) — RED without the runId bump (a timer stays pending).
