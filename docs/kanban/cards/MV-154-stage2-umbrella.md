## Test plan

The umbrella owns no tests. The stage's proof is the union of the slices' coverage, gated by MV-160:

- **MV-155** — a real-DB `*.itest.ts` proving: every pre-existing owner has exactly one personal case; every backfilled row's `case_id` resolves to that owner's personal case; anonymous assessments have `case_id IS NULL`; and the `program_predictions` backfill actually succeeded against the immutability trigger (the negative control matters: a plain `UPDATE … SET case_id` must still raise).
- **MV-156** — the composite-FK rebase holds: an attempt whose `case_id` diverges from its prediction's is rejected; the compensating CHECK bites on the null rows the composite key cannot cover; `owner` accepts NULL on all eight tables **and** the two composite-PK tables were re-keyed rather than "altered" (see Risk notes).
- **MV-157** — repository/route tests proving the personal student experience is unchanged, plus a real-DB check that the dual-write sets both columns and that a consultancy-shaped row (`owner IS NULL`, `case_id` set) round-trips. Uniqueness moved: two open plan items of the same kind in one case are rejected; the same kind across two cases is allowed.
- **MV-158** — dedicated claim tests in the shape the plan demands: create-or-resolve of the personal case, atomicity of `owner` + `case_id`, the primary-assessment partial unique under the demote-then-promote sequence, MV-130's four distinct failure reasons preserved (`already-mine` / `claimed` / `expired` / `error`), and a claim against a purged row still reporting `expired` rather than crashing or resurrecting the row.
- **MV-159** — extends `tests/integration/case-rls.itest.ts`'s discipline to the migrated tables: policies asserted **as the authenticated user**, never service-role; helper functions `STABLE`, `SECURITY DEFINER`, `search_path=''`; `USING` + `WITH CHECK` present on every mutating policy; grants reviewed; cells checked against the canonical access matrix, not against either implementation.
- **MV-160 (the exit gate)** — the before/after regression against production-shaped data, plus the repository sweep. **A green `npm test` is necessary and categorically insufficient**: unit tests cannot prove that a real student's real rows survived a re-key, and they cannot exercise RLS as the authenticated user.

## Integration gate

The umbrella runs no gate of its own; it aggregates the slice gates. The **stage-level** gate every slice must pass:

- `npm run typecheck` · `npm run lint` · `npm test`
- **`npm run test:integration`** — mandatory on **every Stage 2 slice**, because every one of them produces real-DB behaviour (schema change, backfill, constraint swap, policy, or a data-shape guarantee). There is no Stage 2 slice for which unit tests are sufficient evidence.

Locally: `npx supabase start`, then export `SUPABASE_TEST_URL`, `SUPABASE_TEST_SERVICE_ROLE_KEY`, `SUPABASE_TEST_ANON_KEY` from `npx supabase status -o env`.

In CI: `integration` and `validate` are both **required, strict/up-to-date** checks on the protected master ruleset with **no bypass**. A slice cannot merge on a red or skipped integration lane — the `0 skipped` / `✓ <suite>` fail-closed guards MV-153 landed are what make "skipped" count as red. Rebase and re-run before merge is mandatory, not optional.

### The reversibility doctrine (binding on every slice — this is the stage's defining constraint)

Stage 1 was strictly additive and inert on apply. **Stage 2 is not.** Before any slice runs against production:

1. **Rehearse on a copy of live data.** The founder produces a data dump; the agent restores it into a fresh local stack and applies the slice's migration against it. Rehearsing against seed data proves nothing about 76 real assessments with real snapshot shapes.
2. **State the rollback, and execute it in the rehearsal.** A written rollback that was never run is a hypothesis. Roll forward, roll back, roll forward again.
3. **Name the point of no return.** Each slice states the first irreversible act and what makes it irreversible. For the stage as a whole the point of no return is **the first row written with a NULL `owner`** — which is Stage 3, not Stage 2. That is a strong and checkable claim: *Stage 2 remains reversible end to end*, and it stops being reversible the moment consultancy data arrives. It should be protected deliberately, not discovered later.
4. **Reconcile after cutover.** Per-table row counts before and after, plus the owner/`case_id` agreement query. Record the numbers; do not report "looked fine".
5. **No production apply without that record on the card, dated before the apply.** This is the one rule the umbrella enforces on its own slices.
