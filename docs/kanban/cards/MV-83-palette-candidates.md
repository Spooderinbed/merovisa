## Why

The full palette rebrand (founder-locked) replacing deep-teal/warm-paper. Every downstream visual slice (MV-84 system spec, MV-87 rebrand ship, and all Phase 1/2 surfaces) swaps `app/globals.css` token *values* only — **token names are frozen**. This card produces the evidence-driven candidates the founder picks from, each proven accessible before a single pixel ships.

## The 23 frozen semantic tokens (from `app/globals.css`)

Surfaces: `bg` `bg-tint` `surface` `surface-2` · Ink: `ink` `ink-soft` `ink-faint` · Lines: `line` `line-2` · Primary: `primary` `primary-ink` `primary-tint` `primary-tint-2` `on-primary` · Accent: `accent` `accent-tint` · Verdicts: `strong` `strong-tint` `possible` `possible-ink` `possible-tint` `reach` `reach-tint`

Each token gets a light value (`:root`) and a dark value (`.dark`). Rebrand = values-only swap; the `--color-*` aliases in `@theme` and every component reference stay untouched.

## Task

1. **`scripts/contrast-check.mjs`** — runnable Node script (no deps beyond Node built-ins). Imports the candidate palettes from a single data module (`scripts/palette-candidates.data.mjs`) so the script's computed WCAG numbers ARE the doc's matrix (one source of truth, no hand-transcribed ratios). Computes WCAG 2.1 contrast ratios for every meaningful token pair, in both light and dark, flags PASS/FAIL against AA thresholds (4.5:1 normal text, 3:1 large text / UI components), exits non-zero on any FAIL. Prints a per-candidate matrix.
2. **`scripts/palette-candidates.data.mjs`** — the 3 candidates as structured data (23 tokens × light+dark hexes each), plus the pairing spec (which pairs are text-4.5, which are UI-3.0).
3. **`docs/design/2026-07-04-palette-candidates.md`** — for each of 3 candidates: the design rationale (traceable to MV-82 web findings), the full 23-token × light+dark hex table, and the full WCAG matrix (generated from the script, not hand-typed). Ends with a recommendation + the founder-preview instructions.

**Seed directions** (validate/tune against MV-82, don't take on faith): ① "Night indigo" (indigo-violet primary + cool near-white paper — Phantom pole), ② "Deep blue" (saturated blue + glacier-cool paper; flag corporate-generic risk), ③ "Dusk plum" (deep plum/berry + warm sand; most ownable, furthest from teal). Placeless names (brand is global). Verdict trio stays green/amber/red semantic space, re-tuned per candidate, each with a `possible-ink`-style dark text companion on its tint.

## Acceptance criteria

- [ ] `node scripts/contrast-check.mjs` runs clean and **exits 0** — every required pair passes AA in BOTH themes for ALL 3 candidates (if a candidate cannot pass, tune it until it does; a shipped palette that fails WCAG is a defect)
- [ ] `docs/design/2026-07-04-palette-candidates.md` has all 3 candidates, each with the complete 23-token light+dark hex table + the WCAG matrix generated by the script (numbers match the script output exactly)
- [ ] Each candidate's rationale cites specific MV-82 findings (hue ownership, saturation strategy, neutral-ramp step count, dark-mode derivation)
- [ ] Verdict trio (strong/possible/reach + tints + possible-ink companion) present and contrast-proven per candidate
- [ ] Token NAMES unchanged; no `app/globals.css` swap in this slice (candidates live in the data module + doc only); no product code touched
- [ ] Founder-preview instructions included (how to spin a throwaway globals.css swap per candidate for a Vercel preview)
